# 生产候选二次审计（2026-11-02）

本次复核应用源码、安全更新及 Xboard 适配。此记录描述已发现并修复的问题和可复现验证，不代表保证软件不存在其他漏洞；保留旧 sing-box fork 的完整第三方审计不在已完成声明内。

## 修复

- TCP Read/Write 使用累加，三个核心读取清零改成原子交换；节点第一次并发建计数器使用 LoadOrStore，避免覆盖和漏计。
- sing-box 用户 UID 映射加入节点 tag，避免共用 UUID 的节点相互删除计费映射；节点计费阈值 map 的更新与读操作使用同一锁。
- 删除用户及重建入站前保留已产生的流量批次；失败上报继续按 UID 合并，面板明确返回 data=true 才清除。拒绝重定向和隐式重复 POST。
- 原生 Hysteria2 对已撤销用户的存量会话返回断流信号。批量用户修改改为一次加锁循环，避免为每个用户创建 goroutine。
- 控制器核心读写与关闭互斥；关闭取消 HTTP 请求，轮询代次串行，停止后回调不能重建节点。启动失败清理部分节点，关闭幂等并继续清理其他节点。
- 配置监听可取消，重载串行，目录监听支持编辑器原子替换；新核心启动失败尝试恢复旧配置。日志输出文件打开失败保留正常日志目标。
- Xray 普通 TCP 缺 network_settings 时初始化 StreamConfig，修复实际连接测试发现的空指针崩溃。
- sing-box 连接跟踪包装保留 Upstream 元数据，修复 VLESS 首个回包因缓冲区头部空间丢失而崩溃。
- 用户身份校验不接受空、无效或重复身份；SS2022 的短密码返回错误，避免切片越界。重复核心名字和重复节点 tag 明确拒绝。
- Linux CI 增加计数器、面板、任务、配置和核心竞态检查；CodeQL 覆盖实际默认分支；发布压缩包与 Docker 保留本地依赖许可证和安全说明。

## 验证记录

Windows 全发布标签单元测试和 go vet 已运行。三个核心实际本地监听通过 VLESS / 原生 Hysteria2 将数据转发到 TCP echo，核对返回内容和双向计费。测试只为回环地址增加测试文件内的例外，生产私网阻断保持启用；Xray 使用仅测试的 freedom 出站规则。覆盖范围不等于所有协议、所有客户端配置和真实面板端到端验收。

Linux 全测试、race、真实 TCP socket 协议检查、QUIC trailer 回归、32/128 并发、三个核心各 180 秒自然内存观察及升级/回滚脚本模拟测试均已通过。
验收应用源码为 `f682dcb6d68d60cacb9f6067bcc63c0643c731a5`，
[Actions run 41473791934](https://github.com/rmomo5285-droid/V2bX/actions/runs/41473791934)。
原始数据与 RSS/堆内存结果见 `validation-linux-20261102.md`。随后文档与发布工作流的调整不改动应用源码；版本标签发布仍重新执行该标签源码的完整验证。

标签首轮多架构构建发现 Android 的 `anet` 依赖使用 Go 私有 `net.zoneCache`，
缺少上游要求的 Go 1.23+ 链接参数。发布工作流仅为 Android 添加
`-checklinkname=0`，其他平台保留默认检查；不修改应用依赖或源码。
固定后的工作流可通过 `release_tag` 手动输入重新验证、构建已有标签，
所有检出仍固定到通过验证的标签提交。Android 只做交叉编译，未验证设备运行。
参考：[anet 官方构建说明](https://github.com/wlynxg/anet#how-to-build-with-go-1230-or-later)。

后续 Linux 复验在周期齐发的 128 并发 Hysteria2 短连接中记录了 10 次拒绝，
已阻止 `.1` 发布。`.2` 将短连接的速率控制修正为共享时钟，并保留原模式以便复现；
持久连接的同时起连、失败即拒绝发布、内容与计费一致性检查均保留。
生产接入队列和重试策略不变，容量突发可能被拒绝的限制仍存在。

`.2` 的连续五轮 Linux 完整会话 churn 仍失败，亦未发布。`.3` 常规短连接验收
按 Hysteria2 的复用模型为每个客户端保留 QUIC 会话，反复开关 TCP 流；独立记录
QUIC 会话数，保留 128 会话同步握手和原始完整会话 churn 诊断入口。
未把每秒大量 TLS/QUIC 重建的容量边界称为已修复。详见 `stress-testing.md`。

## 保留边界

待确认流量仅在进程内存；崩溃、进程重启或全局重建控制器仍可能丢失。面板未提供幂等键，丢失应答后的跨周期重试可能重复计费。删除用户与最后一次数据包并发时也不能保证逐字节精确结算。新配置及回退都失败时需人工恢复，不能保证无中断。

GO-2026-5288（Hysteria OOM）及 GO-2026-5932（OpenPGP 状态）保留在安全报告中，未以扫描工具证明没有漏洞。MPTCP 默认关闭仅缓解公开利用路径，Linux CVE-2026-98432 仍须厂商内核修复并重启；显式开启 MPTCP 的配置会覆盖 Go 默认值。

尚未验证 Docker 构建、全部发布架构的运行、真实生产面板和线上负载；未连接或改动用户服务器。发布状态以 GitHub Release 为准，默认分支源码推送和发布均不等于服务器已升级。

参考：[Go 官方 MPTCP 说明](https://github.com/golang/go/issues/82717)、[Go 1.27.3 正式版本](https://go.dev/doc/devel/release#go1.27.3)、[Ubuntu CVE 追踪](https://ubuntu.com/security/CVE-2026-98432)。
