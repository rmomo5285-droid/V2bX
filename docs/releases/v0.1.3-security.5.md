# v0.1.3-security.5

Xboard compatibility improvements now retain failed accounting batches, support
v2 and machine-token authentication for explicitly configured nodes, distinguish
empty user lists from HTTP 304, allow idle nodes to start, preserve device counts
on alive-query failures, and retry snapshots after failed core updates. Background
task generations have isolated stop signals. See `docs/upstream-integration.md`
for source references, configuration, tests and delivery limitations.

Go 1.27.3 rebuild of V2bX v0.1.2 with default MPTCP disabled, current Xray and
REALITY forks matching the v2node update on 2026-11-02, Hysteria2 2.13.0 and
updated security-sensitive Go dependencies. Native Hysteria2 UDP target changes
now propagate to the configured outbound ACL; fragmented sniffing and panel
rules have regression coverage. An offline systemd upgrade helper verifies
SHA-256, backs up the binary and rolls back on initial service failure.

The sing-box QUIC fork also contains a source backport of the upstream
CVE-2026-40898 fix, limiting decoded HTTP/3 trailer fields. Dedicated tests
cover expansion, validation and early termination. Renamed forks and local
replacements are not reliably covered by automated upstream CVE matching.
The remaining Hysteria `GO-2026-5288` scanner finding has no database fix
version; V2bX now caps each UDP sniff operation at 64 KiB and rejects larger
inputs before they reach the parser. This is a bound, not a claim of upstream
resolution.

The sing-box panel fork is preserved as pinned source with one REALITY private
key compatibility patch. Go 1.27 builds require `http2legacy`; CI/Docker/release
commands include it. See `third_party/README.md` for provenance and limits.

Check existing configs: the current Xray removed legacy transport headers
`srtp`, `tls`, `utp`, `wechat-video` and `wireguard`, Shadowsocks `none`/`plain`,
and the `DisableIVCheck` option. TLS/REALITY transports remain available.

This is an application mitigation, not a Linux kernel fix. Install the vendor
kernel update for CVE-2026-98432 and boot it. Until then, disable MPTCP at the
host/network-namespace level and restart existing listeners. Explicit MPTCP
options and GODEBUG overrides bypass the build default. See
`docs/security-mptcp.md`.

Release archives retain their existing platform names and include SHA-256
sidecars. `update-security.sh` downloads this fixed release, verifies the archive
and rollback helper, then upgrades an existing standard systemd installation.
Check the entry script against its independently confirmed release checksum
before executing it. Connections are interrupted by the service restart;
configuration, certificates and geodata are preserved. See
`docs/security-upgrade.md` for supported layouts and rollback limits.

Validation uses a mock Xboard panel, actual localhost proxy listeners and
TCP echo in the parent process; clients run in a separate process on the same
host. Stress runs fix GOMAXPROCS=2 per process. Full tests, QUIC/security
regressions, focused race checks, 32/128-client workloads, five same-node
Hysteria2 stream-churn rounds, three 180-second natural idle observations,
updater/rollback tests and vet are required. Every workload error still fails
acceptance. Memory and goroutines cover the parent, including mock panel and
echo; no forced GC occurs before the 180-second sample. Each Hysteria2 churn
worker retains one QUIC session and repeatedly opens/closes TCP streams.
Persistent mode starts 128 independent transports together.

Known capacity failure, not claimed fixed: .4 passed its release validation but
failed two independent runs of the same source (41488777130, 41488777222),
including refused Hysteria2 connections and delayed cleanup. It was moved from
Latest to prerelease. The controlled comparison 41494156018 passed 15 rounds
with separate clients and GOMAXPROCS=2; separate clients at GOMAXPROCS=1 still
had 14 connection errors. Shared-process groups also failed. Production queue
sizes, retry behavior and runtime defaults have not changed. These results do
not guarantee burst capacity on a limited CPU host, WAN bandwidth, a maximum
user count, or long-term memory behavior. All failures and reproduction modes
remain documented in docs/release-cross-check-20261103.md and stress-testing.md.
No production server was connected or upgraded.

Release automation now stops at an asset-verified draft. Publication requires
reviewing independent checks for the same immutable source; a single successful
run is insufficient evidence when other runs fail.

CodeQL follow-up: .3 was cancelled before publication to address newly uploaded
analysis results. This release confines external UI ZIP extraction with os.Root,
rejects traversal, archive symlinks and existing symlink escapes, bounds download
and extracted sizes, and fixes archives containing a root-level index.html.
DNS-over-HTTP/3 responses are limited to 65,535 bytes regardless of Content-Length.
Port/early-data conversions reject invalid ranges, empty HTTP transport paths
return errors, UID conversions are bounded, and direct Tor/REALITY/CCM credential
logging is removed. Local-fork regressions and an archive negative control cover
the changes. The archive implementation requires Go >=1.25; this release uses
Go 1.27.3. CodeQL findings for Trojan's protocol SHA-224 and custom TLS public-key
pinning are contextual findings, not a reason to change the wire protocol or
disable pin verification. Error-log taint findings remain documented; a clean
scanner report is not claimed.
