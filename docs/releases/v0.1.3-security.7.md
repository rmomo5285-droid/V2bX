# v0.1.3-security.7

Fixes live VLESS Vision traffic accounting when Xray uses Linux TCP splice.
The optimized path now accounts successful splice batches as they are forwarded,
so active downloads reach the panel without waiting for the connection to close.
Unlimited users keep the optimized splice path; limited or unknown wrappers use
the counted reader/writer path. No traffic multiplier was changed.

Connection management now registers concurrent links atomically and releases
them when their contexts end. User revocation closes the active connection.
Counter readers preserve data returned together with EOF and honor configured
timeouts. Access-log status reporting distinguishes new failures from historical
totals and reports recovery without retrying an ambiguous POST.

Linux CI uses real TLS-over-VLESS downloads and verifies that panel push totals
match bytes written by the target for plain VLESS, Vision with splice enabled,
and Vision with splice disabled. The Vision auto case also verifies positive
Linux splice syscalls. Multi-user stress runs cover 150 and 300 users with four
long-lived streams each, one CPU and 1 GiB, three rounds without restart,
access-log timeout and recovery, live traffic reports, online heartbeats, and
connection cleanup. Test clients, target and mock panel share the cgroup; these
measurements are not a production VPS capacity guarantee.

The Linux updater verifies SHA-256 for the platform archive and rollback helper,
backs up the current executable, and restores it if the new service does not
start cleanly. The update restarts V2bX and interrupts active connections;
configuration, certificates, geodata and access-log settings are preserved.
Use the pinned-checksum update command in the release instructions, then verify
panel traffic and client connectivity. The application update does not replace
the vendor Linux kernel fix required for CVE-2026-98432.
